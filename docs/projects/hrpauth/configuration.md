# Configuration & API

The service reads a single `config.yaml` from the project root. This page explains how the file is handled and documents every field.

## Configuration Lifecycle

On startup the service processes the file in this order.

1. Check whether `config.yaml` exists
2. Write the default configuration if it does not
3. Read the `version` field if it does
4. Apply the chain migration when the version is older than the binary supports
5. Only warn, and never rewrite the file, when the version is newer than the binary

Migration behavior details:

- **Automatic backup**: the original file is backed up as `config.yaml.bak.<old_version>` before migration (only one backup per version is kept; existing backups are not overwritten).
- **Migration failure** terminates startup; the original file remains untouched (it was backed up before migration, so it can be rolled back manually). Startup also terminates when the `version` field is missing or there is no migration path for the version.
- **Atomic write**: migration persists through a temporary file + rename, avoiding partially written configuration files.

## Schema Versions

The top-level `version` field is the configuration schema version. Upgrades are chain-linked, one migration function per version (`config/migrations.go`). Current version: **13** — `oauth2.service_clients` is an optional list that seeds OAuth2 service clients at startup (a missing or empty list seeds nothing); `database.port` is optional; `database.host` carries the hostname, and the inline `ip:port` form in `host` stays compatible (when `port` is set, the inline part is stripped).

## Complete `config.yaml` Example

```yaml
version: "13"
site:
  name: "HRPAuth"
  implementation: "HRPAuth"
  version: "1.0.0"
server:
  port: ":2778"
  cors_origin: "*"
callback:
  url: "https://backend.auth.example.com/"
frontend:
  url: "https://auth.example.com/"
database:
  host: "localhost"
  port: 3306
  db_name: "hrpauth"
  user: "root"
  password: ""
  charset: "utf8mb4"
  retry_interval_sec: 3
  max_retries: 5
  next_round_delay_min: 5
verification_code:
  code_ttl: 600
  storage_dir: "./cache/verification_codes"
redis:
  host: "localhost"
  port: 6379
  password: ""
  db: 0
  prefix: "hrpauth_"
smtp:
  host: "smtp.example.com"
  port: 587
  username: ""
  password: ""
  encryption: "tls"
  from_email: "noreply@example.com"
  from_name: "HRPAuth"
manage:
  token: "<auto-generated on first startup>"
security:
  password_cost: 10              # bcrypt cost for native and reset-updated HRPAuth passwords
  rate_limit_max_attempts: 10    # Max login failure count
  rate_limit_window_sec: 600     # Login failure window (seconds)
  enable_captcha: true           # Enable graphical captcha (mandatory validation for /register)
  captcha_ttl: 300               # Captcha TTL (seconds), stored in Redis
webauthn:
  rp_display_name: ""            # Defaults to site.name
  rp_id: ""                      # Defaults to the domain derived from rp_origins
  rp_origins: []                 # Defaults to the callback/frontend URLs
  session_ttl_sec: 300
oauth2:
  service_clients: []            # Optional; seeded at startup. Each entry: client_id, client_secret, optional name. Empty/missing seeds nothing
core_api:
  internal_key: "<auto-generated on first startup>"
yggdrasil_api:
  base_url: "http://localhost:2770"
  internal_key: "<auto-generated on first startup>"
sdk_packages:
  storage_dir: "./data/sdk_packages"
  max_package_size: 20971520
  max_packages: 128
```

## Field Reference

| Section | Field | Type | Default | Description |
|-------|-------|------|---------|-------------|
| top-level | `version` | string | — | Configuration schema version (current `"13"`) |
| `site` | `name` / `implementation` / `version` | string | `"HRPAuth"` / `"HRPAuth"` / `"1.0.0"` | Service identity; appears in `GET /status` and Yggdrasil `meta.serverName` |
| `server` | `port` | string | `":2778"` | Listening port (must include colon) |
| `server` | `cors_origin` | string | `"*"` | CORS allowed Origin |
| `callback` | `url` | string | — | Backend callback address (appears as `site.url` in the `GET /` status response) |
| `frontend` | `url` | string | — | Frontend page address |
| `database` | `host` / `db_name` / `user` / `password` | string | — | MySQL connection |
| `database` | `port` | int | `0` | MySQL port; `0` keeps the legacy behavior, in which `host` may carry an inline `ip:port` (that inline form stays compatible) |
| `database` | `charset` | string | — | Character set, recommended `utf8mb4` |
| `database` | `retry_interval_sec` / `max_retries` / `next_round_delay_min` | int | `3` / `5` / `5` | Connection retry interval, max retries, delay before the next retry round (`0` disables further rounds) |
| `verification_code` | `code_ttl` | int | `600` | Verification code TTL (seconds) |
| `verification_code` | `storage_dir` | string | `"./cache/verification_codes"` | Directory for verification code JSON files |
| `redis` | `host` / `port` / `password` / `db` / `prefix` | — | `"localhost"` / `6379` / `""` / `0` / `"hrpauth_"` | Redis connection and key namespace |
| `smtp` | `host` / `port` / `username` / `password` | — | — | SMTP server |
| `smtp` | `encryption` | string | — | `"tls"` / `"starttls"` / `"none"` |
| `smtp` | `from_email` / `from_name` | string | — | Sender address and display name |
| `security` | `password_cost` | int | `10` | bcrypt cost for newly generated or reset-updated passwords |
| `security` | `rate_limit_max_attempts` / `rate_limit_window_sec` | int | `10` / `600` | Login failure limit and window |
| `security` | `enable_captcha` | bool | `true` | Graphical captcha (mandatory validation for `/register`) |
| `security` | `captcha_ttl` | int | `300` | Captcha TTL in Redis (seconds) |
| `webauthn` | `rp_display_name` | string | `site.name` | Relying party display name |
| `webauthn` | `rp_id` | string | derived from `rp_origins` | Relying party ID (domain) |
| `webauthn` | `rp_origins` | array | derived from callback/frontend URLs | Allowed origins for WebAuthn ceremonies |
| `webauthn` | `session_ttl_sec` | int | `300` | WebAuthn ceremony session TTL (seconds) |
| `oauth2` | `issuer` | string | `callback.url` | OAuth2 issuer metadata base URL |
| `oauth2` | `authorization_code_ttl_sec` / `access_token_ttl_sec` / `refresh_token_ttl_sec` | int | `300` / `3600` / `2592000` | Token TTLs |
| `oauth2` | `super_client_id` / `super_client_secret` | string | `hrpauth-internal-super` / generated | Built-in low-friction service client |
| `oauth2` | `super_client_extra_scopes` | array | `[]` | Additional scopes for the built-in super client; only `db.*` scopes are accepted, others silently ignored |
| `oauth2` | `public_client_id` / `public_redirect_uris` | — | `hrpauth-webui` / `["<frontend>/oauth/callback"]` | Built-in public client for the first-party WebUI |
| `oauth2` | `service_clients` | array | `[]` | Optional list of OAuth2 service clients seeded at startup; each entry carries `client_id`, `client_secret` and an optional `name` (falls back to `client_id`). A missing or empty list seeds nothing |
| `manage` | `token` | string | auto-generated | **Manage Token (M-T)**: accepted as a management credential; for service-to-service calls prefer the OAuth2 super client |
| `core_api` | `internal_key` | string | generated | The core reads no `core_api` value at all; satellites configure their own `core_api` block in their own configuration files |
| `yggdrasil_api` | `base_url` | string | `http://localhost:2770` | Base URL of the HRPAuth-Yggdrasil-API service; the core uses it for the `/internal/heartbeat` ping. The generated `internal_key` in this block is not read by the core either |
| `sdk_packages` | `storage_dir` / `max_package_size` / `max_packages` | — | `"./data/sdk_packages"` / `20971520` / `128` | Compile-time SDK package store |

Notes:

- First-party WebUI login uses `authorization_code + PKCE`; service-to-service integration uses `client_credentials` with the built-in super client or an independent service client.
- `oauth2.service_clients` is seeded idempotently at startup: a missing row is created as a confidential `client_credentials` client with `is_super=false` (its tokens resolve as service tokens, which satisfy ops-level auth checks); an existing row is never modified — a manually rotated secret is not clobbered — and a config/database drift only produces a warning.
- Internal callback authentication uses dynamic temporary keys issued via `POST /services/auth-key`, not static configuration values.
- The OAuth2 built-in super client secret carries the main service-to-service power; protect it as a service-level credential.
- During BlessingSkin import, bcrypt hashes may be copied directly while non-bcrypt sources are converted into the fixed marker `BS2HA$RESET_REQUIRED` and must use password reset later.
- After modifying `config.yaml`, the **service must be restarted** to take effect (no hot reloading).

## Yggdrasil Protocol Blocks (HRPAuth-Yggdrasil-API service)

Since the 2026-10 service split, the `yggdrasil.*` configuration blocks live in the [HRPAuth-Yggdrasil-API](/projects/hrpauth-yggdrasil-api/) service, not in the HRPAuth core. They are kept here for reference.

### `yggdrasil.server`

Controls what the Minecraft ecosystem sees.

- `name`, `implementation`, `version`
- `signature_public_key_path`, `signature_private_key_path`
- `textures_storage`
- `links.homepage`, `links.register`
- `skin_domains`

When `links` is empty the metadata falls back to values derived from `frontend.url`.

### `yggdrasil.security`

- `token_expiry_days`
- `session_expiry_seconds`
- `max_texture_width`, `max_texture_height`: size limits in pixels, returned as a notice instead of a rejection
- `max_texture_file_size`: size limit in bytes, uploads above it are rejected
- `max_tokens_per_user`: how many valid `accessToken` records one user may hold

### `yggdrasil.feature_flags`

Protocol compatibility switches. See [Feature Flags](/projects/hrpauth/configuration#feature-flags) below.

## Token Types

| Name | Field | Scope | Issued by |
|---|---|---|---|
| OAuth2 access token | `access_token` | Business routes | `/oauth/token`, `/totp/verify` |
| OAuth2 refresh token | `refresh_token` | Token renewal | `/oauth/token` |
| Login ticket | `login_ticket` | Temporary TOTP credential | `/oauth/login-ticket` |
| Yggdrasil access token | `accessToken` | Minecraft client sessions | `/authserver/authenticate` |
| Yggdrasil client token | `clientToken` | Paired with the access token | `/authserver/authenticate` |

## Feature Flags

| Flag | Effect |
|---|---|
| `non_email_login` | Allow a character name instead of an email to log in |
| `legacy_skin_api` | Keep the legacy `GET /skins/MinecraftSkins/{username}.png` route |
| `no_mojang_namespace` | Drop the Mojang namespace from profile properties |
| `enable_mojang_anti_features` | Expose Mojang anti-cheat related metadata |
| `enable_profile_key` | Enable the Minecraft 1.19+ chat signing keys |
| `username_check` | Validate the Minecraft character name format |
| `enable_ip_check` | Verify the IP in `hasJoined` against the session record |

These switches live under `yggdrasil.feature_flags` in the HRPAuth-Yggdrasil-API service configuration and only affect the protocol layer, never the business layer.

## Route Groups

### Business routes

`/oauth/*`, `/register`, `/logout`, `/forgot-password`, `/reset-password`, `/user`, `/user/lookup`, `/user/deleted`, `/change-username`, `/user/security/*`, `/webauthn/*`, `/email-verification`, `/email-2fa/*`, `/totp/*`, `/captcha/*`, `/internal/*`.

### Yggdrasil routes

`/authserver/*`, `/sessionserver/*`, `/api/profiles/minecraft`, texture routes, `/minecraftservices/*`. Since the 2026-10 split these are served by the [HRPAuth-Yggdrasil-API](/projects/hrpauth-yggdrasil-api/) service; the core only relays the `/yggdrasil-api` prefix to it.

### Extension routes

`/services/presence`, `/services/auth-key`, `/services/route`, `/services/hook`, `/services/relay`, `/services/sdk-packages`.

## Easily Misread Points

- `callback.url` is the backend address; `frontend.url` is the frontend site address. The metadata fallback uses the latter.
- The captcha settings belong to the top-level `security` block, not to `yggdrasil.security`.
- A business OAuth2 access token and a Yggdrasil `accessToken` are unrelated. Mixing them produces errors that look reasonable but mean nothing.

## Smoke Test

After a fresh start, check these two routes first.

- `GET /status`
- `GET /`

If both answer, the business layer and the Yggdrasil metadata are at least serving traffic.
