# 文档编写规范

为了让这套 wiki 能长期维护并保持风格统一，所有新增页面都建议遵循下面这些规范。

## 页面结构

每篇文档尽量包含这几个部分：

- 页面目标：说明这篇文档解决什么问题
- 背景信息：帮助读者快速建立上下文
- 正文内容：按任务或主题分块组织
- 相关链接：指向上下游文档

## 标题层级

- 一个页面只保留一个一级标题
- 二级标题用于拆分主要章节
- 三级标题用于补充细节，不要层级过深
- 标题面向读者表达，文件名面向维护者表达

## 写作建议

- 标题尽量直接，避免使用模糊命名
- 一段只表达一个主要观点
- 操作步骤用有序列表
- 命令、路径、配置项统一使用代码格式
- 提到具体项目时使用其正式名称，不要使用目录名代替

## 项目页面的固定骨架

`projects/` 下的每个项目页面都从下面这几节开始，方便读者横向比较：

- 一句话定位：这个项目负责什么
- 技术栈：语言、框架、依赖的外部服务
- 目录结构：顶层目录职责清单
- 如何运行：构建命令、运行命令、依赖服务
- 配置：配置文件位置与关键配置项
- 与其它项目的关系：依赖谁、被谁依赖

核心项目会额外拆出架构说明和配置或接口参考页；外围项目只保留上面这一页。

## 链接维护

- 新增页面后，记得更新导航或侧边栏
- 涉及上下游流程时，补充相关文档链接
- 删除或重命名页面时，及时检查失效链接
- 站内链接统一使用绝对路径，例如 `/zh/projects/hrpauth/`

## 语言约定

英文站是默认语言，`/zh/` 是其镜像。两种语言保持页面结构一致，新增页面时同步补齐另一侧。

## 内容生命周期

不同文档的更新频率会不同，建议用下面的方式维护：

- 高频变化内容：放在更新记录、FAQ 或操作指南
- 低频变化内容：放在架构说明、内容模型、规范文档
