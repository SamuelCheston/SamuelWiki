# 配置与接口

服务只读取项目根目录下的一个 `config.yaml`。本页说明这个文件如何被处理，并逐一记录每个字段。

## 配置生命周期

启动时按以下顺序处理配置文件。

1. 检查 `config.yaml` 是否存在
2. 不存在则写入默认配置
3. 存在则读取 `version` 字段
4. 版本低于当前二进制支持范围时，执行链式迁移
5. 版本高于当前二进制支持范围时，仅告警，绝不重写文件

迁移行为细节：

- **自动备份**：迁移前原文件备份为 `config.yaml.bak.<old_version>`（每个版本只保留一份备份，已有备份不覆盖）。
- **迁移失败**即终止启动，原文件保持不动（迁移前已备份，可手工回滚）。`version` 字段缺失或没有迁移路径时同样终止启动。
- **原子写入**：迁移通过临时文件 + 重命名落盘，避免写出半截配置文件。

## Schema 版本

顶层 `version` 字段是配置 schema 版本。升级按版本逐级链式迁移，每个版本一个迁移函数（`config/migrations.go`）。当前版本：**12**。

| 版本 | 变化 |
|---------|---------|
| `1.0` | 初始 YAML 配置（`memcache` 验证码，无 redis） |
| `2` | 新增 `redis`；`memcache` 更名为 `verification_code` |
| `3` | `security` 字段（含验证码）从 `yggdrasil.security` 移到顶层 `security`；新增 `manage.token`；`redis.prefix` 默认 `hrpauth_` |
| `4` | 新增 `oauth2` 节（站内 OAuth2 授权） |
| `5` | 新增 `yggdrasil.security.max_texture_file_size`（贴图上传大小上限，默认 512000） |
| `6` | 新增顶层 `storage` 节，含 `orphan_file_expiry_days`（默认 7） |
| `7` | 新增 `oauth2.super_client_extra_scopes`（数据库 scope 委托） |
| `8` | 拆分 yggdrasil：引入 `core_api` 与 `yggdrasil_api` 节用于服务间通信 |
| `9` | 新增顶层 `sdk_packages` 节（编译期 SDK 聚合） |
| `10` | 移除 `core_api` 与 `yggdrasil_api` 的静态 `internal_key`；内部服务鉴权改用 OAuth2 动态临时密钥 |
| `11` | 新增数据库连接重试配置：`database.retry_interval_sec`（默认 3）、`database.max_retries`（默认 5）、`database.next_round_delay_min`（默认 5） |
| `12`（当前） | 新增可选 `database.port`；`database.host` 不再需要内联 `ip:port` 写法（旧的内联写法仍然兼容） |

## 完整 `config.yaml` 示例

```yaml
version: "12"
site:
  name: "HRPAuth"
  implementation: "HRPAuth"
  version: "1.0.0"
server:
  port: ":2778"
  cors_origin: "*"
callback:
  url: "https://backend.auth.example.com/"
frontend:
  url: "https://auth.example.com/"
database:
  host: "localhost"
  port: 3306
  db_name: "hrpauth"
  user: "root"
  password: ""
  charset: "utf8mb4"
  retry_interval_sec: 3
  max_retries: 5
  next_round_delay_min: 5
verification_code:
  code_ttl: 600
  storage_dir: "./cache/verification_codes"
redis:
  host: "localhost"
  port: 6379
  password: ""
  db: 0
  prefix: "hrpauth_"
smtp:
  host: "smtp.example.com"
  port: 587
  username: ""
  password: ""
  encryption: "tls"
  from_email: "noreply@example.com"
  from_name: "HRPAuth"
manage:
  token: "<auto-generated on first startup>"
security:
  password_cost: 10              # 原生与重置更新的 HRPAuth 密码的 bcrypt cost
  rate_limit_max_attempts: 10    # 登录失败次数上限
  rate_limit_window_sec: 600     # 登录失败窗口（秒）
  enable_captcha: true           # 图形验证码（/register 强制校验）
  captcha_ttl: 300               # 验证码 TTL（秒），存 Redis
webauthn:
  rp_display_name: ""            # 默认 site.name
  rp_id: ""                      # 默认取 rp_origins 推导出的域名
  rp_origins: []                 # 默认取 callback/frontend URL
  session_ttl_sec: 300
core_api:
  internal_key: "<首次启动自动生成>"
yggdrasil_api:
  base_url: "http://localhost:2770"
  internal_key: "<首次启动自动生成>"
sdk_packages:
  storage_dir: "./data/sdk_packages"
  max_package_size: 20971520
  max_packages: 128
```

## 字段参考

| 节 | 字段 | 类型 | 默认值 | 说明 |
|-------|-------|------|---------|-------------|
| 顶层 | `version` | string | — | 配置 schema 版本（当前 `"12"`） |
| `site` | `name` / `implementation` / `version` | string | `"HRPAuth"` / `"HRPAuth"` / `"1.0.0"` | 服务标识；出现在 `GET /status` 与 Yggdrasil `meta.serverName` |
| `server` | `port` | string | `":2778"` | 监听端口（必须带冒号） |
| `server` | `cors_origin` | string | `"*"` | 允许的 CORS 来源 |
| `callback` | `url` | string | — | 后端回调地址（在 `GET /` 状态响应中显示为 `site.url`） |
| `frontend` | `url` | string | — | 前端页面地址 |
| `database` | `host` / `db_name` / `user` / `password` | string | — | MySQL 连接 |
| `database` | `port` | int | `0` | MySQL 端口；`0` 保持旧行为，此时 `host` 可以内联 `ip:port`（旧的内联写法仍然兼容） |
| `database` | `charset` | string | — | 字符集，建议 `utf8mb4` |
| `database` | `retry_interval_sec` / `max_retries` / `next_round_delay_min` | int | `3` / `5` / `5` | 连接重试间隔、最大重试次数、下一轮重试前的延迟（分钟）；`0` 禁用后续重试轮次 |
| `verification_code` | `code_ttl` | int | `600` | 邮箱验证码 TTL（秒） |
| `verification_code` | `storage_dir` | string | `"./cache/verification_codes"` | 验证码 JSON 文件目录 |
| `redis` | `host` / `port` / `password` / `db` / `prefix` | — | `"localhost"` / `6379` / `""` / `0` / `"hrpauth_"` | Redis 连接与键命名空间 |
| `smtp` | `host` / `port` / `username` / `password` | — | — | SMTP 服务器 |
| `smtp` | `encryption` | string | — | `"tls"` / `"starttls"` / `"none"` |
| `smtp` | `from_email` / `from_name` | string | — | 发件地址与显示名 |
| `security` | `password_cost` | int | `10` | 新生成或重置更新密码的 bcrypt cost |
| `security` | `rate_limit_max_attempts` / `rate_limit_window_sec` | int | `10` / `600` | 登录失败上限与窗口 |
| `security` | `enable_captcha` | bool | `true` | 图形验证码（`/register` 强制校验） |
| `security` | `captcha_ttl` | int | `300` | 图形验证码在 Redis 中的 TTL（秒） |
| `webauthn` | `rp_display_name` | string | `site.name` | Relying party 显示名 |
| `webauthn` | `rp_id` | string | 由 `rp_origins` 推导 | Relying party ID（域名） |
| `webauthn` | `rp_origins` | array | 由 callback/frontend URL 推导 | WebAuthn 仪式允许的来源 |
| `webauthn` | `session_ttl_sec` | int | `300` | WebAuthn 仪式会话 TTL（秒） |
| `oauth2` | `issuer` | string | `callback.url` | OAuth2 issuer 元信息基础 URL |
| `oauth2` | `authorization_code_ttl_sec` / `access_token_ttl_sec` / `refresh_token_ttl_sec` | int | `300` / `3600` / `2592000` | 令牌 TTL |
| `oauth2` | `super_client_id` / `super_client_secret` | string | `hrpauth-internal-super` / 生成 | 内置低运维成本服务客户端 |
| `oauth2` | `super_client_extra_scopes` | array | `[]` | 内置 super client 的附加 scope；只接受 `db.*`，其余静默忽略 |
| `oauth2` | `public_client_id` / `public_redirect_uris` | — | `hrpauth-webui` / `["<frontend>/oauth/callback"]` | 第一方 WebUI 的内置公开客户端 |
| `manage` | `token` | string | 首次启动自动生成 | **旧版 Manage Token（M-T）**，仅为向后兼容保留，新集成不要使用 |
| `core_api` | `internal_key` | string | 自动生成 | 拆分遗留：核心不读取任何 `core_api` 值。卫星服务在各自的配置文件中维护自己的 `core_api` 块 |
| `yggdrasil_api` | `base_url` | string | `http://localhost:2770` | HRPAuth-Yggdrasil-API 服务地址，核心用它发起 `/internal/heartbeat` 探活。该块中的 `internal_key` 同样不被核心读取 |
| `sdk_packages` | `storage_dir` / `max_package_size` / `max_packages` | — | `"./data/sdk_packages"` / `20971520` / `128` | 编译期 SDK 包存储 |

说明：

- 第一方 WebUI 登录使用 `authorization_code + PKCE`；服务间集成使用 `client_credentials`（内置 super client 或独立的服务客户端）。
- 内部回调鉴权使用 `POST /services/auth-key` 动态签发的临时密钥，不再使用静态配置值。
- OAuth2 内置 super client secret 承载了主要的服务间权限，请按历史 M-T 的级别保护它。
- BlessingSkin 导入时，bcrypt 哈希可能直接复制，非 bcrypt 来源会被转换为固定标记 `BS2HA$RESET_REQUIRED`，用户须通过重置密码找回访问。
- 修改 `config.yaml` 后必须**重启服务**才生效（无热加载）。

## Yggdrasil 协议配置块（HRPAuth-Yggdrasil-API 服务）

2026-10 服务拆分后，`yggdrasil.*` 配置块属于 [HRPAuth-Yggdrasil-API](/zh/projects/hrpauth-yggdrasil-api/) 服务，不再属于 HRPAuth 核心。此处保留供参考。

### `yggdrasil.server`

控制 Minecraft 生态看到的内容。

- `name`、`implementation`、`version`
- `signature_public_key_path`、`signature_private_key_path`
- `textures_storage`
- `links.homepage`、`links.register`
- `skin_domains`

`links` 为空时，元信息会回退到由 `frontend.url` 推导出的值。

### `yggdrasil.security`

- `token_expiry_days`
- `session_expiry_seconds`
- `max_texture_width`、`max_texture_height`：像素尺寸上限，超出时以 notice 形式返回而不是直接拒绝
- `max_texture_file_size`：字节大小上限，超出时拒绝上传
- `max_tokens_per_user`：单个用户最多持有的有效 `accessToken` 数量

### `yggdrasil.feature_flags`

协议兼容开关，见下面的[功能开关](#功能开关)。

## 令牌类型

| 名称 | 字段 | 作用范围 | 颁发接口 |
|---|---|---|---|
| OAuth2 access token | `access_token` | 业务路由 | `/oauth/token`、`/totp/verify` |
| OAuth2 refresh token | `refresh_token` | 令牌续期 | `/oauth/token` |
| Login ticket | `login_ticket` | TOTP 二步验证临时凭据 | `/oauth/login-ticket` |
| Yggdrasil access token | `accessToken` | Minecraft 客户端会话 | `/authserver/authenticate` |
| Yggdrasil client token | `clientToken` | 与 access token 配对 | `/authserver/authenticate` |

## 功能开关

| 开关 | 作用 |
|---|---|
| `non_email_login` | 允许用角色名而非邮箱走 Yggdrasil 登录 |
| `legacy_skin_api` | 保留旧的 `GET /skins/MinecraftSkins/{username}.png` 路由 |
| `no_mojang_namespace` | 去掉资料属性里的 Mojang 命名空间 |
| `enable_mojang_anti_features` | 暴露 Mojang 反作弊相关元信息 |
| `enable_profile_key` | 启用 Minecraft 1.19+ 聊天签名密钥 |
| `username_check` | 校验 Minecraft 角色名格式 |
| `enable_ip_check` | 校验 `hasJoined` 中的 IP 与会话记录是否一致 |

这些开关位于 HRPAuth-Yggdrasil-API 服务配置的 `yggdrasil.feature_flags` 下，只影响协议层，不影响站内业务层。

## 路由分组

### 业务路由

`/oauth/*`、`/register`、`/logout`、`/forgot-password`、`/reset-password`、`/user`、`/user/lookup`、`/user/deleted`、`/change-username`、`/user/security/*`、`/webauthn/*`、`/email-verification`、`/email-2fa/*`、`/totp/*`、`/captcha/*`、`/internal/*`。

### Yggdrasil 路由

`/authserver/*`、`/sessionserver/*`、`/api/profiles/minecraft`、纹理路由、`/minecraftservices/*`。自 2026-10 拆分后，这些路由由 [HRPAuth-Yggdrasil-API](/zh/projects/hrpauth-yggdrasil-api/) 服务提供，核心只把 `/yggdrasil-api` 前缀中继过去。

### 扩展路由

`/services/presence`、`/services/auth-key`、`/services/route`、`/services/hook`、`/services/relay`、`/services/sdk-packages`。

## 容易误解的点

- `callback.url` 是后端地址，`frontend.url` 是前端站点地址。元信息的回退逻辑用的是后者。
- 验证码配置属于顶层 `security` 块，不在 `yggdrasil.security` 里。
- 站内 OAuth2 access token 与 Yggdrasil `accessToken` 毫无关系。混用会得到一堆看起来合理、实际毫无帮助的报错。

## 联调检查

全新启动后，先检查这两个接口。

- `GET /status`
- `GET /`

两个都有响应，说明站内业务层和 Yggdrasil 元信息至少已经能对外工作。
